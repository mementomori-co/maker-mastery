# Slicing from the command line (Windows)
Applies to: both (H2C and P1S) · Bambu Studio 02.08.02.61 (source read at tag v02.08.02.61 and at master)
Verified: 2026-10-04

## Facts
- Basic command shape: `"<Bambu Studio install>\bambu-studio.exe" --debug 3 --slice 0 --export-3mf OUT.3mf --outputdir <out folder> <IN.3mf>`. `--slice` takes 0 for all plates or i for plate i; `--export-3mf` exports the project as 3MF; `--outputdir` sets where output files go; `--debug` sets the log level from 0 (fatal) to 5 (trace). — [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) (CLI option definitions near L9964-10332 at master)
- The official CLI documentation is the GitHub repository wiki, not wiki.bambulab.com. Its example slices all plates of a sample 3MF with `--slice 0 --debug 2 --export-3mf`. It does not describe `result.json`. — [Command-Line-Usage](https://github.com/bambulab/BambuStudio/wiki/Command-Line-Usage)
- `result.json` is written to the output directory (or the working directory) by `record_exit_reson` in `BambuStudio.cpp`. Top-level keys include `plate_index`, `return_code`, `error_string`, `times`, `peak_rss_mb`, `layer_height`, `wall_loops`, `sparse_infill_density` and `sliced_plates[]`. Each plate entry carries `id`, `times{}`, `triangle_count`, `warning_message`, `total_predication`, `main_predication`, `filament_change_times`, `layer_filament_change`, `feature_type_times{}` (Outer wall, Inner wall, Support, Flush, Prime tower, Travel and others), `objects[]` and `filaments[]` (`filament_id`, `main_used_g`, `total_used_g`). — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/BambuStudio.cpp) L488-632
- Warnings: the CLI runs the same `Print::validate()` as the GUI. A warning never changes `return_code`; errors (exclusion area, clumping-detection area) do fail the slice. Some warnings reach `result.json` `warning_message` (a "floating regions" warning has been observed there), but the prime-tower "too close to others" warning has been observed with an empty `warning_message`. Read `warning_message` on every plate and check prime-tower clearance yourself. — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/BambuStudio.cpp) L7067-7142, [Print.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Print.cpp) L949-1055; observation: not verified (no public source), verify on your own install
- A sliced 3MF written by `--export-3mf` contains `Metadata/project_settings.config`, `Metadata/model_settings.config`, `Metadata/slice_info.config`, `Metadata/filament_sequence.json`, per-plate `Metadata/plate_N.json` and `plate_N.gcode.md5`, plus the G-code. `plate_N.json` was seen in real files but its writer was not located in the exporter source. — [bbs_3mf.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Format/bbs_3mf.cpp) L156-190
- `bambu-studio.exe` is built as a Windows GUI-subsystem program (`add_executable(BambuStudio_app_gui WIN32 ...)`, output name `bambu-studio`); its `wWinMain` only reattaches standard streams to the parent terminal via the Win32 attach-to-parent call and `freopen("CONOUT$")`. In practice `--help` printed nothing on Windows and redirected stdout/stderr came back empty under every launch method tried, even for an error the source writes to `cerr`. Treat any "grep the log" check as unproven unless you can capture output on your own install. — [CMakeLists.txt](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/CMakeLists.txt), [BambuStudio_app_msvc.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/BambuStudio_app_msvc.cpp) L197-199, [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/BambuStudio.cpp) L6984

### Loading configs and how presets merge
- `--load-settings` loads process/machine settings from a `;`-separated file list; `--load-filaments` loads filament settings the same way; `--arrange` takes 0 (off), 1 (on) or other (auto). — [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L10140-10257
- The wiki says loaded files must be full configs, not the leaf files under `resources/profiles/BBL/machine` or `.../process`; at most one machine and one process setting are supported. Priority: command line, then `--load-settings`/`--load-filaments`, then what is already in the 3MF. — [Command-Line-Usage](https://github.com/bambulab/BambuStudio/wiki/Command-Line-Usage)
- `load_from_json` does not resolve `inherits` or `include` by itself: unless asked to load inherits, both keys are only copied into an output map, never applied. — [Config.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Config.cpp) L839-844, L951-955; [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L4133
- `--load-config-file`: `from` must be `system`, `User` or `user` (case-sensitive) and `type` must be `machine`, `process` or `filament`; anything else returns `CLI_CONFIG_FILE_ERROR`. — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/BambuStudio.cpp) L2320-2342, L2424-2425
- A missing `resources/profiles/BBL/{machine,process,filament}_full/<name>.json` only logs a warning ("can not find system preset file") and falls back to the original preset. — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/BambuStudio.cpp) L2777, L2818, L2889, L2927, L2949
- Preset merge order in `PresetBundle.cpp`: start from the `inherits` parent (or the type default); then apply each `include` file's keys that differ from that include's own default; then apply the preset's own keys last. Precedence is therefore own keys, then `include` diffs, then the `inherits` parent. The JSON key names are `inherits` and `include`. — [PresetBundle.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PresetBundle.cpp) L4859, L4885-4894, L4908; [Preset.hpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Preset.hpp) L56-57
- Example of that chain in Bambu's own profiles: H2C filament leaves such as `Bambu PLA Basic @BBL H2C.json` inherit from an `@base` parent (which holds `filament_id`) and include a dual-extruder filament template; the H2C machine profile includes one template per G-code block (start, end, time-lapse, change-filament, layer-change and others). — [BBL filament profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/filament), [BBL machine profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/machine)
- Filament `compatible_printers` lists are scoped per nozzle variant: an H2C 0.4 mm filament preset and a 0.6 mm preset are separate leaf files, each listing only its own `Bambu Lab H2C 0.x nozzle`, while `filament_id` sits in the shared `@base` parent. — [BBL filament profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/filament)

### Return codes, argument parsing and G-code header units
- Not every config key works as a CLI flag. The parser (`DynamicConfig::read_cli`) turns a key into a flag by replacing underscores with dashes, but keys marked `nocli` are excluded (for example `compatible_printers`, `inherits`, `filament_settings_id`, `printer_model`). `curr_bed_type`, `filament_map` and `filament_map_mode` are not `nocli`. — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/BambuStudio.cpp) L8333, [Config.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Config.cpp) L245-255, L1660, [PrintConfig.hpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.hpp) L1866
- `return_code -61` ("Filaments are not compatible with the plate type") is raised when the filament's bed temperature for the current plate type is 0. The code-default bed is Cool Plate, and Bambu PETG profiles set `cool_plate_temp` to 0, so a 3MF without an explicit bed type can fail this way; setting `curr_bed_type` to a supported plate clears it. — [Print.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L1677, [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp) L439, L1313, [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/BambuStudio.cpp) L6989
- `return_code -100` ("Failed slicing the model. Please verify the slicing of all plates...") was observed when re-slicing a CLI-exported 3MF that had never been sliced (no `Metadata/plate_1.gcode` inside); a 3MF that had already been sliced re-sliced fine. The code path was not traced. — not verified (no public source); the message site is in [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/BambuStudio.cpp) L169; verify on your own install
- G-code header units: the line `; total filament volume [cm^3]` has been observed to hold a value in mm3, not cm3 (length x pi x (1.75/2)^2 matched it, and weight / value matched the filament density only if the value is read as mm3 / 1000). — not verified (no public source); check on your own G-code with the method above

## In practice
- Keep `result.json` next to its exact input and read `return_code` there; do not rely on stdout/stderr text on Windows.
- Read `warning_message` on every plate, and run your own prime-tower clearance check, because that warning may not appear in `result.json`.
- Read `feature_type_times.Support` per plate: a non-zero value while `enable_support = 0` means a per-object override or a different input file.
- When loading settings through the CLI, pass full configs, or resolve the `inherits`/`include` chain yourself first, in the slicer's order (parent, then includes, then own keys).
- Before re-slicing a 3MF with the CLI, check that it already contains G-code; otherwise slice it once (GUI or CLI) first.
- If precise filament volume matters, compute it from the header's filament length and diameter.
- When picking an H2C filament preset, match the leaf's `compatible_printers` to the nozzle diameter actually installed.
