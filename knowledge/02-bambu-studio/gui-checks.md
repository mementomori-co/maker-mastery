# GUI-only checks and how to replicate them in code
Applies to: both (H2C and P1S) · Bambu Studio 02.08.02.61 (source tag v02.08.02.61)
Verified: 2026-10-05

Some Bambu Studio warnings appear in the GUI but are not reliably reported by the CLI. If you slice from the command line, every check that matters for a print file must either be replicated in your own code or listed as "not proven".

## Facts
- The CLI surfaces some warnings in `result.json` `warning_message` (for example a "floating regions" warning has been observed there) but the prime-tower clearance warning has been observed missing. Read `warning_message` on every plate and do not treat an empty value as proof. — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/BambuStudio.cpp) L7067-7142; observation: not verified (no public source), verify on your own install. See [cli-slicing.md](cli-slicing.md).
- Prime-tower clearance (GUI soft warning "Prime Tower is too close to others..."): `layered_print_cleareance_valid` intersects each object's raw 2D convex hull (no brim, no skirt, no `extruder_clearance_radius`) with the tower outline. To replicate: take the tower body plus first-layer brim footprint from the sliced G-code, compare it with every object hull from the 3MF, and require a safety gap. See [grouping-and-purge.md](grouping-and-purge.md). — [Print.cpp v02.08.02.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L944-1051
- "No sparse layers" compacted-tower check (GUI hard error, added in 2.8.2): runs only when `wipe_tower_no_sparse_layers` is on, the print order is by layer and a tower exists. If your profiles leave that key off, the check is dormant; confirm by resolving your profile chain. — [Print.cpp v02.08.02.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L3347-3567
- Per-extruder printable area on the H2C: the left and right nozzles reach different X ranges, so a plate using both extruders must keep objects inside the overlap. Replicate by comparing object bounding boxes and every G-code extrusion point against `extruder_printable_area` from the machine profile. — [BBL machine profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/machine) (key `extruder_printable_area`); see the printer notes in [../01-printers/](../01-printers/)
- Filament grouping / mapping (dialog "Filament grouping"): `filament_map_mode` `Auto For Flush` = Filament-Saving, `Auto For Match` = Convenience, `Manual` = Custom; per-plate `filament_maps` 1 = LEFT, 2 = RIGHT. Replicate by reading the per-plate mode and maps from the 3MF and the `; filament_map =` line from the G-code header, and comparing them with what is physically loaded. — [grouping-and-purge.md](grouping-and-purge.md)
- Supports: `enable_support` gates all support generation, but per-object or modifier overrides (`enable_support`, `support_type`, `enforce_support_layers`) in `model_settings.config` can turn supports on for one object. Replicate by reading project and per-object keys and counting Support / Support interface feature lines in the G-code. — see [support-settings.md](support-settings.md)
- Filament vs printer/nozzle compatibility: the GUI refuses a filament preset whose `compatible_printers` does not list the selected printer and nozzle variant. Replicate by looking up each `filament_settings_id` in the profile bundle and checking its `compatible_printers` against `printer_settings_id` and the nozzle diameter of the extruder it is mapped to. — [BBL filament profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/filament)
- Nozzle hardness: the GUI string for `NOZZLE_HRC_CHECKER` still exists, but the checker that would raise it is commented out in `GCodeProcessor::update_slice_warnings()`, so 02.08.02.61 does not warn about nozzle hardness. A check of `nozzle_type` against the filament's `required_nozzle_HRC` would be a new rule of your own, not a replication. — [Plater.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/slic3r/GUI/Plater.cpp) L7951, [GCodeProcessor.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/GCode/GCodeProcessor.cpp) L6368-6400
- Bed type vs filament (hard error): `Print::validate()` reads the filament's bed-temperature key for the current bed type and, when it is 0, raises "Plate %d: %s does not support filament %s". Bambu profiles set 0 for plates they do not recommend (for example PETG `cool_plate_temp`). Replicate by failing on a 0 bed temperature for the chosen plate. — [Print.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L1669-1689, [BBL filament profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/filament)
- Bed temperature vs softening: the GUI string `BED_TEMP_TOO_HIGH_THAN_FILAMENT` (open the door and/or remove the upper glass) exists, but at this tag `update_slice_warnings()` pushes only time-lapse warnings, so it is never emitted. The standing guidance is the `temperature_vitrification` tooltip: when the bed is at or above the softening temperature, opening the front door and/or removing the upper glass is highly recommended to avoid clogs. A check of bed temperature against `temperature_vitrification` is a rule from the tooltip, not a replicated warning. — [Plater.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/slic3r/GUI/Plater.cpp) L7949, [GCodeProcessor.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/GCode/GCodeProcessor.cpp) L6351-6420, [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp) L3003-3005
- Printer-specific door/vent guidance: on H2-series printers the slicer sets the air-management mode by filament type and the top vent opens with the exhaust fan; on the P1S the wiki recommends an open door and/or removed top cover for PLA on a hot plate. — [H2 cooling fan system](https://wiki.bambulab.com/en/h2/manual/cooling-fan-system), [heat creep](https://wiki.bambulab.com/en/filament-acc/filament/heat-creep)
- Sparse infill at 100 % with a non-solid pattern: the GUI config check rejects patterns such as Grid at 100 % density (allowed set: Concentric, Rectilinear, Aligned Rectilinear, Hilbert Curve, Archimedean Chords, Octagram Spiral), but the CLI has been observed to slice it anyway with no warning and incompletely filled layers. Replicate by failing the pair `sparse_infill_density = 100%` plus a non-allowed `sparse_infill_pattern`, resolved per part, then per object, then project. — [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp) L9528-9531; CLI behaviour: not verified (no public source), verify on your own install
- Out-of-bed and height: compare object bounds with the bed and the machine profile's `printable_height`. Object-to-object overlap needs its own check.

## In practice
1. Slice with the CLI, then run your own checks on the output (3MF metadata, tower clearance, G-code extrusion bounds, support lines, filament map); never trust an empty `warning_message`.
2. List every check you have not replicated as "not proven" in your pre-print checklist, with the manual step that covers it (for example opening the file in the GUI).
3. When you meet a new GUI warning, record its source function and either the code that replicates it or "NOT replicated".

## Not verified / open questions
- Where the Windows build writes its log output, if anywhere.
- Whether `wipe_tower_rotation_angle` is fixed at 0 in the H2C and P1S profiles (the post-generation clearance test ignores it).
- Whether a newer Bambu Studio re-enables the bed-temperature or nozzle-hardness slice warnings; re-check `update_slice_warnings()` after upgrading.
