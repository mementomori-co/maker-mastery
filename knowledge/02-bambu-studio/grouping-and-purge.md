# Filament grouping, purge and prime tower (H2C)
Applies to: H2C (grouping, purge, rib-wall and 3MF sections) · both (prime-tower clearance geometry) · Bambu Studio 2.8.x (source read at master and at tags v02.08.02.61 / v02.08.04.61; line numbers valid for the snapshot cited in each fact)
Verified: 2026-10-04

## Facts
- Grouping modes in the GUI: Filament-Saving Mode (default), Convenience Mode and Custom (plus Quality Mode on some printers). The H2C manual says that with two or more filaments the automatic grouping will always put one of them on the left hotend. — [H2C manual V1.0 section 6.2.1](https://csm.bblcdn.com/hub/eff78da43720461787dc8bbe5fa0372d.pdf), [Studio H2C operation](https://wiki.bambulab.com/en/h2c/manual/bambu-studio-h2c-operation). Studio 2.8.2 notes: with only one filament change, Filament-Saving now tries to follow the actual left/right filament arrangement. — [releases](https://github.com/bambulab/BambuStudio/releases)
- The wiki lists the three modes in the floating window of the slice button: Filament-Saving (default), Convenience (groups by the filaments actually in your AMS) and Custom. Quality Mode is documented under a heading for the X2D; whether the H2C offers it is not stated. — [dual-nozzle grouping](https://wiki.bambulab.com/en/software/bambu-studio/manual/dual-nozzles-slicing-filament-grouping)
- "The H2C currently does not support TPU printing with the left nozzle." — [dual-nozzle grouping](https://wiki.bambulab.com/en/software/bambu-studio/manual/dual-nozzles-slicing-filament-grouping)

### `filament_map_mode`: values, labels, storage
- Config key `filament_map_mode`, type enum, Advanced mode, default `Auto For Flush`. The C++ enum has six members: `fmmAutoForFlush, fmmAutoForMatch, fmmManual, fmmNozzleManual, fmmAutoForQuality, fmmDefault`; only the three `AutoFor*` members count as automatic. — [PrintConfig.hpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.hpp) L384-391, L412-414; [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L2526-2541
- Serialized strings (config JSON and 3MF): `Auto For Flush` (Filament-Saving), `Auto For Match` (Convenience), `Manual` (Custom), `Nozzle Manual`, `Auto For Quality` (Quality). `fmmDefault` has no string. The option's `enum_values` and `enum_labels` lists are in different orders, so do not derive value-to-label mapping from them. — [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L532-539, L2530-2539
- Legacy value `Auto` is rewritten to `Auto For Flush` when a config loads; the 3MF plate reader treats `Auto` as an old file and leaves the plate key unset. — [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L7554-7556; [bbs_3mf.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Format/bbs_3mf.cpp) L4759-4767
- GUI labels: dialog "Filament grouping" with two tabs, "Auto" (shown as "Fila Saving" in some states) and "Custom" (= `Manual`). Inside Auto: Filament-Saving Mode, Convenience Mode, Quality Mode. — [FilamentMapDialog.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/FilamentMapDialog.cpp) L276-315, L405-409; [FilamentMapPanel.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/FilamentMapPanel.cpp) L658-660
- Filament-Saving and Convenience are always candidates; Quality only when the plate uses different extruder types. Convenience is removed when the filament switcher is ready, and greyed out (falling back to Filament-Saving) when the printer is not synced. — [FilamentMapDialog.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/FilamentMapDialog.cpp) L96-114, L335-336; [FilamentMapPanel.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/FilamentMapPanel.cpp) L679
- A plate with no `filament_map_mode` returns `fmmDefault`, which means "use the project value". — [PartPlate.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/PartPlate.cpp) L303-314, L4093-4099; [Plater.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/Plater.cpp) L25651-25655
- 3MF storage: the project value is in `Metadata/project_settings.config`; the per-plate value is a `<metadata key="filament_map_mode">` inside each `<plate>` of `Metadata/model_settings.config`, written only when the plate has a named mode (a `Default` plate writes nothing). Plate `filament_maps` / `filament_volume_maps` are written only alongside a plate mode. — [bbs_3mf.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Format/bbs_3mf.cpp) L8211-8219, L8526-8549
- CLI behaviour (observed, 02.08.02.61, H2C): passing `--filament-map-mode Manual --filament-map 2` set the project value to `Manual`, but the plate entry in `model_settings.config` still read `Auto For Flush`; the G-code's embedded config nevertheless showed `; filament_map = 2` and `; filament_map_mode = Manual`. — not verified (no public source); check the G-code header on your own slices

### Which `filament_map` value is LEFT vs RIGHT on the H2C
- Value 1 = LEFT, value 2 = RIGHT. Evidence: the grouping panel puts `filament_map == 1` on the left panel and `== 2` on the right; `DevDefs.h` sets `MAIN_EXTRUDER_ID = 0` (right) and `DEPUTY_EXTRUDER_ID = 1` (left); the H2C device file `O1C.json` names extruder id 0 "Right Extruder" and 1 "Left Extruder"; the H2C machine profile has `physical_extruder_map ["1","0"]`. — [FilamentMapPanel.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/slic3r/GUI/FilamentMapPanel.cpp) L285, [DevDefs.h](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/DeviceCore/DevDefs.h) L98-100, [O1C.json](https://raw.githubusercontent.com/bambulab/BambuStudio/master/resources/printers/O1C.json) L86, [BBL machine profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/machine)
- The project-level `filament_map ["1"]` default is just the one-entry default; the per-plate `filament_maps` is what drives a slice. `filament_map_2` ("Filament map plus for multi nozzle") indexes the extruder-and-nozzle-volume table; `physical_extruder_map` maps logical to physical extruder; `master_extruder_id` is set to 2 in the H2C 0.4 mm profile. — [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L2509-2524, L5157-5160
- Only Manual-mode GUI edits are confirmed to write `filament_maps` onto a plate; where an auto-mode result is stored on the plate was not located. — [bbs_3mf.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Format/bbs_3mf.cpp) L8531-8534, [Plater.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/Plater.cpp) L26833-26840
- `first_extruder` in `Metadata/plate_N.json` is a 0-based filament index in printing order, not an extruder number (the tool ordering re-indexes extruders to be zero-based). Do not read `first_extruder: 0` as "left". — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/BambuStudio.cpp) L8073, [ToolOrdering.hpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/GCode/ToolOrdering.hpp) L312, [ToolOrdering.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/GCode/ToolOrdering.cpp) L316-320, L1136
- `GCodeWriter::toolchange()` has an `M1020 S<filament_id> H<nozzle_id>` branch for Bambu printers, but H2C G-code has been observed to use plain `T0`/`T1` plus the `change_filament_gcode` template (`M620 S[next_extruder]A ...`) instead. — [GCodeWriter.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/GCodeWriter.cpp) L405; observation: not verified (no public source)

### CLI mapping precedence when regrouping a sliced 3MF
- Precedence, highest first: CLI `--filament_map_mode` / `--filament_map`; the plate's own value; the project value as a fallback when the plate stores none. — [BambuStudio.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/BambuStudio.cpp) L6656-6659, L6703-6745; [PartPlate.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/slic3r/GUI/PartPlate.cpp) L288-310
- On load, a previously sliced 3MF's per-plate `filament_maps` in `Metadata/slice_info.config` overrides the one in `model_settings.config`: the same metadata handler parses both and `slice_info.config` is read later. `slice_info.config` carries only `filament_maps`, not the mode. — [bbs_3mf.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Format/bbs_3mf.cpp) L1678-1682, L4657-4675, L8692-8698
- So editing only `model_settings.config` of a sliced 3MF can leave the old grouping in force. To regroup for the CLI, set the mode and map in the project config, in every `<plate>` of `model_settings.config` and in every `<plate>` of `slice_info.config`, and accept the result only from the sliced G-code header (`; filament_map = ...`, `; filament_map_mode = Manual`). — method derived from the source rows above; verify on your own slice
- In Manual mode the extruder comes from `filament_map`; on the H2C right side, the hotend is chosen by the slicer's flush-minimising grouping and written as `filament_nozzle_map`. — [FilamentGroup.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/FilamentGroup.cpp) L1539-1548, [ToolOrdering.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/GCode/ToolOrdering.cpp) L1904-1928
- Moving a filament from the left extruder to a second right-side hotend can raise the slicer's time estimate, because a right-side hotend change is booked as an unload plus load rather than a quick extruder switch. — not verified (no public source; slicer estimates only); compare `result.json` times on your own file

### Purge, pre-cooling, prime tower
- Purge modes: config key `prime_volume_mode` (`Default` / `Saving` / `Fast`, default `Default`). Dialog "Purge Mode Settings": Standard (full purging with speed and temperature transition) and Prime Saving (less waste, faster, may cause slight colour mixing); the wiki calls it "Purge Saving". With `Saving`, every wipe volume is forced to 15 mm3. The button appears only for the H2C. — [Print.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Print.cpp) L3429-3431, L3983-3987; [PurgeModeDialog.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/PurgeModeDialog.cpp); [H2C purge mode](https://wiki.bambulab.com/en/software/bambu-studio/h2c-purge-mode)
- After slicing, filaments are bound to their hotend; the send page cannot move a filament to the other extruder. — [H2C manual V1.0 section 6.2.1](https://csm.bblcdn.com/hub/eff78da43720461787dc8bbe5fa0372d.pdf), [dual-nozzle grouping](https://wiki.bambulab.com/en/software/bambu-studio/manual/dual-nozzles-slicing-filament-grouping)
- Pre-cooling is a filament setting: Filament > Multi Filament > "Precooling target temperature" with "Extruder change" (`filament_pre_cooling_temperature`) and "Hotend change" (`filament_pre_cooling_temperature_nc`); 0 = disabled. "Multi extruder pre cooling" / "pre heating" are G-code comments, not settings. — [PrintConfig.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L3115-3136, [Tab.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/Tab.cpp) L4743-4762, [GCodeProcessor.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/GCode/GCodeProcessor.cpp) L6710-6753
- Prime tower rib-wall keys (all Advanced mode): `prime_tower_rib_wall` "Rib wall" (default true; forces a square cross-section so width is fixed), `prime_tower_rib_width` "Rib width" (default 8 mm, max 300), `prime_tower_fillet_wall` "Fillet wall" (default true), `prime_tower_extra_rib_length` "Extra rib length" (default 0 mm), `prime_tower_skip_points` "Skip points" (default true). — [PrintConfig.cpp v02.08.04.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.04.61/src/libslic3r/PrintConfig.cpp) L6451-6490
- GUI location: Process > Others > Prime tower, in the order Skip points, Rib wall, Extra rib length, Rib width, Fillet wall. — [Tab.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/slic3r/GUI/Tab.cpp) L3512-3521
- The five rib-wall keys are absent at tag v01.10.02.76 and present at v02.00.00.95, with no tag between, so they shipped in Bambu Studio 2.0.0, whose release note lists a rib outer wall and outer-wall filleting. — [tags API](https://api.github.com/repos/bambulab/BambuStudio/tags?per_page=100), [release note 2.0.0](https://wiki.bambulab.com/en/software/bambu-studio/release/release-note-2-0-0), [PrintConfig.cpp v01.10.02.76](https://raw.githubusercontent.com/bambulab/BambuStudio/v01.10.02.76/src/libslic3r/PrintConfig.cpp), [PrintConfig.cpp v02.00.00.95](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.00.00.95/src/libslic3r/PrintConfig.cpp)
- The wiki calls the feature an external reinforcement rib design for vibration and impact resistance; its "Extra rib length: 10mm" image is an example, not the default. — [prime tower wiki](https://wiki.bambulab.com/en/software/bambu-studio/parameter/prime-tower)
- H2C process profiles use `prime_tower_width 60` and `prime_tower_brim_width -1` (auto), with no override of the rib-wall keys. — [BBL process profiles](https://github.com/bambulab/BambuStudio/tree/master/resources/profiles/BBL/process); verify on your installed bundle

### Prime tower clearance checks (source reading, tag v02.08.02.61)
- Layered-print check `layered_print_cleareance_valid` (sic): the object side is the raw 2D convex hull of each model part, with no brim, no skirt and no margin. The tower side is a bare `prime_tower_width` x depth rectangle before the tower is generated, and the tower mesh's bottom outline afterwards (without re-applying `wipe_tower_rotation_angle`). For the plain tower that outline only partly covers the real brim; for the rib tower it is the brim-grown rib section. — [Print.cpp v02.08.02.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L944-1051, L5289-5313
- The test is a plain intersection with zero margin. Tower-vs-object overlap gives the non-fatal warning "Prime Tower is too close to others, and collisions may be caused."; overlap with the exclusion or clumping-detection area is a hard error. `extruder_clearance_radius` is not used here (only in the sequential-print check). — [Print.cpp v02.08.02.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L1036-1049
- A separate "No sparse layers" check `compacted_wipe_tower_clearance_valid` first appears in 2.8.2. It runs only with `wipe_tower_no_sparse_layers` on, by-layer print order and a tower present; it pads the pre-slice tower estimate by brim width plus 2 x nozzle diameter, grows tower and object hulls by half of `extruder_clearance_max_radius` each, and raises a hard error telling you to move the model, lower it or turn off "No sparse layers". In `validate()` the layered check runs first. — [Print.cpp v02.08.02.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L1353-1370, L3347-3567; [Print.cpp v02.08.01.55](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.01.55/src/libslic3r/Print.cpp) (absent); [Print.cpp v02.08.02.60](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.60/src/libslic3r/Print.cpp) (present)
- In the GUI a soft warning appears as a "WARNING:" notification; a hard error appears as an "Error:" notification and hides the slicing progress bar. — [Plater.cpp v02.08.02.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/slic3r/GUI/Plater.cpp) L10898-10902, L10995-11025; [NotificationManager.cpp v02.08.02.61](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/slic3r/GUI/NotificationManager.cpp) L1671, L1697-1698

## In practice
- Avoid nozzle switching where you can by printing one material per part or plate.
- If only the right inlet has an AMS, use Custom grouping with every AMS filament on the RIGHT (value 2). Before slicing, read `filament_map_mode` and `filament_maps` from the 3MF and refuse `Auto For Flush` when nothing is loaded on the left.
- When auditing a 3MF, read each plate's `filament_map_mode` first, fall back to the project value, match on the serialized strings, and treat legacy `Auto` as `Auto For Flush`. For a sliced 3MF also read `slice_info.config` and the G-code header.
- Never put TPU on the H2C left extruder.
- The source clearance test has zero margin and ignores most of the brim, so keep a generous gap (for example 8 mm or more) between the measured tower-plus-brim footprint in the G-code and every object's hull, and check it yourself.
