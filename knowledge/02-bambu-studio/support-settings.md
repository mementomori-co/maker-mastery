## Facts

### Enable support, max bridge length, don't support bridges
- Support > Enable support `enable_support`: code default **false**; all H2C 0.4 mm presets keep it off. -- [PC](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp); [COMMON](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/resources/profiles/BBL/process/fdm_process_common.json)
- Tree support generation is gated on it: when `enable_support` is false the tree generator logs that tree support is disabled and returns before generating anything. -- [TreeSupport.cpp (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Support/TreeSupport.cpp) L664
- Support > Max bridge length `max_bridge_length` (Advanced mode): the tooltip says 0 supports all bridges and a very large value supports none. Code default 10 mm; COMMON sets **0**, so every BBL process profile inherits 0. -- [PrintConfig.cpp (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L2065-2072; [fdm_process_common.json (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/resources/profiles/BBL/process/fdm_process_common.json)
- Support > Don't support bridges `bridge_no_support`: default false; the tooltip says it skips supporting the whole bridge area. -- [PrintConfig.cpp (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) L2049-2055
- **Which one counts depends on the support type.** Tree support reads `max_bridge_length` (it derives its own bridge flag from `max_bridge_length > 0`) and never reads the `bridge_no_support` key. Classic (normal) support declares `max_bridge_length` but never uses it; bridge removal there runs on `bridge_no_support` alone. Both need `enable_support` on. -- [TreeSupport.cpp (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Support/TreeSupport.cpp) L679-680, L1272-1276; [SupportMaterial.cpp (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Support/SupportMaterial.cpp) L1394-1395, L1512-1515
- When bridges are broken at contacts, a bridge line longer than `max_bridge_length + 10` mm is divided equally. -- [PrintObject.cpp (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintObject.cpp) L4494-4501, L4542-4545
- A line in Print.cpp that appears to skip objects without `enable_support` sits inside an `#if 0` block and is never compiled; it is not a support gate. -- [Print.cpp (master)](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/Print.cpp) L1472-1496

### Type and style
- Support type `support_type` (normal(auto), tree(auto), normal(manual), tree(manual); code default normal(auto)): the manual types only generate support on enforcers. All five H2C 0.4 mm presets resolve to **tree(auto)** (set in COMMON). -- [PC](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp); [COMMON](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/resources/profiles/BBL/process/fdm_process_common.json)
- Support style (Default, Grid, Snug, Tree Slim, Tree Strong, Tree Hybrid, Tree Organic): all presets resolve to Default. With tree(auto) and Default, the code picks **Tree Organic** unless the object has variable layer heights or a soluble interface, in which case it picks Tree Hybrid. So same-filament PLA at a fixed layer height gets Tree Organic. The wiki line calling Tree Hybrid the current default is stale. -- [SP](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Support/SupportParameters.hpp) L143-151; [SW](https://wiki.bambulab.com/en/software/bambu-studio/support)
- The wiki says hybrid(auto) moved from type to style after version 1.4.1; Normal support usually gives a better surface on large flat overhangs, while tree or hybrid gives stronger support with less material and time on complex, small, non-planar overhangs. -- [SW](https://wiki.bambulab.com/en/software/bambu-studio/support)
- Tree Organic is refused for objects with variable layer height (adaptive layers or a height-range modifier). In the GUI the message says variable layer height is not supported with Organic supports. A command-line slice fails with `return_code` -51 (validation error) and only a generic "incorrect slicing parameters" text. -- [Print.cpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Print.cpp) L1436-1442; [Utils.hpp](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Utils.hpp) L51; [SP](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Support/SupportParameters.hpp) L144

### Interface and spacing
- Support interface pattern "Default" = **Rectilinear Interlaced** at this version: both share the rectilinear contact pattern, and the interface angle alternates +45 / -45 deg per interface layer unless the style is Grid or the pattern is plain Rectilinear. The wiki's older text on default interface patterns is stale for this version. -- [SP](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/Support/SupportParameters.hpp) L176-177, L313-317; [PC](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp)
- Spacing (preset values for 0.12 HQ / 0.16 HQ / 0.16 Std / 0.20 HQ / 0.20 Std): Top Z distance and Bottom Z distance 0.12 / 0.16 / 0.16 / 0.2 / 0.2 mm; Threshold angle 20 / 25 / 25 / 30 / 30 deg; Support/object XY distance 0.35 mm in all; Support/object first layer gap code default 0.2 mm. The wiki advises about 0.2 mm Top Z (not 0) when the interface is the same filament as the part, or the support is very hard to remove. -- [PC](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp); [BBL process folder](https://github.com/bambulab/BambuStudio/tree/v02.08.02.61/resources/profiles/BBL/process); [SW](https://wiki.bambulab.com/en/software/bambu-studio/support)
- Interface layers: top code default 3, preset 2; bottom code default 0 (-1 = same as top), preset 2. Top interface spacing default and preset 0.5 mm; 0 means a solid interface and is required for support ironing. The wiki says 0 interface layers can sag, 3 gives a stable flat platform, and 0 bottom interface layers is very bad for the support's first layer. -- [PC](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp); [SW](https://wiki.bambulab.com/en/software/bambu-studio/support)
- Other keys: On build plate only (default false); Support critical regions only (Advanced mode, default false; supports only critical regions such as sharp tails and cantilevers); Remove small overhangs (default true); Independent support layer height (default true; invalid while the prime tower is on). In `0.20mm Standard @BBL H2C`: base pattern Default, base spacing 2.5 mm, tree branch angle 45 deg (code 40), branch diameter 2 mm (code 5), tree wall count -1 (auto). The wiki defines critical overhangs as small ones, ones supported at one end only, and ones far from other parts. -- [PC](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/src/libslic3r/PrintConfig.cpp); [COMMON](https://raw.githubusercontent.com/bambulab/BambuStudio/v02.08.02.61/resources/profiles/BBL/process/fdm_process_common.json); [SW](https://wiki.bambulab.com/en/software/bambu-studio/support)
- Details on Top Z rounding per style: [support-top-z-same-filament.md](support-top-z-same-filament.md). Enforcers, critical regions and tip rules: [support-enforcers-and-critical-regions.md](support-enforcers-and-critical-regions.md).

### Tree support code facts (source reading)
- **Support blockers do not keep tree trunks or branch feet off a region.** The tree generator subtracts blocker areas only from the overhang areas that need support; no blocker subtraction is applied to branch or trunk-base areas, and branches are not routed around blockers. -- [TS](https://github.com/bambulab/BambuStudio/blob/v02.08.02.61/src/libslic3r/Support/TreeSupport.cpp) L880-970, L1077-1078
- **No "Tip diameter" option exists in 02.08.02.61.** The 0.8 mm tip used for enforcer overhangs is a code constant. Tip size follows Process > Support > Branch diameter (1-10 mm), and thickening toward the plate follows Branch diameter angle (0-15 deg). -- [TS](https://github.com/bambulab/BambuStudio/blob/v02.08.02.61/src/libslic3r/Support/TreeSupport.cpp) L696
- **Raft expansion has no effect on tree support**: the tree raft area is offset by a fixed 3 mm. -- [TS](https://github.com/bambulab/BambuStudio/blob/v02.08.02.61/src/libslic3r/Support/TreeSupport.cpp) L1591
- **Support > Initial layer expansion (`raft_first_layer_expansion`) widens tree trunk footprints on the first layer, with or without a raft**: with no raft it is used as the tree brim width and as the layer-0 expand offset. Larger values merge separate trunk feet into fewer, bigger footprints at a small cost in filament and time. -- [TS](https://github.com/bambulab/BambuStudio/blob/v02.08.02.61/src/libslic3r/Support/TreeSupport.cpp) L1596, L2336, L2476-2478

### Removal timing
- The wiki advises removing support within about 2 hours for moisture-sensitive cases, naming nylon (PA), PVA and PA/PET support material; PLA is not the named case. -- [SW](https://wiki.bambulab.com/en/software/bambu-studio/support)

## In practice
- Test it yourself: slice one small bridge coupon four ways (support off with max bridge length 0 and 10; support on with 0 and a very large value) and compare the slicer's time estimate and the count of support lines in the G-code. On tree(auto) you should see that max bridge length only matters when support is enabled.
- Blockers cannot move tree trunks or feet. To keep feet off a surface, turn On build plate only on (some branches may then be lost where they cannot reach the plate), model your own support pillars, or accept the feet.
- To check blocker or expansion effects on your own part, slice with and without the change and compare support in Preview (Line Type view) and the first layer.
- The best fix is geometry: 45 deg roofs, teardrop holes, keels and chamfers need no support.
- Resolve a profile value through its whole `inherits` chain before trusting it; the leaf JSON rarely holds the key.
- Start from `0.20mm Standard @BBL H2C`; the 0.16 High Quality preset has much slower outer walls, so justify it per part.
